# 브라우저 테스트 (E2E)

실제 크롬으로 390×844 모바일 뷰포트에서 게임을 직접 플레이하는 스크립트다.
단위 테스트(`npm test`)는 엔진 계산만 검증하므로, 실제 플레이 검수는 여기서 한다.

## 준비

```bash
npm run build
npm run preview -- --port 4173     # http://localhost:4173/band-game/
npm i -D playwright                # 최초 1회 (프로젝트 의존성에는 넣지 않음)
```

## 실행

```bash
node tests/e2e/smoke.mjs      # 전체 동선 + 개발자 문자열 / 탭 영역 / 월드 회귀
node tests/e2e/phase2a.mjs    # 새 게임에서 7주 연속 플레이 (성장 루프)
node tests/e2e/compat.mjs     # PHASE 2A 이전 형태의 세이브 로드 + 계속 플레이
node tests/e2e/practicecost.mjs  # 합주·연습이 장부에 별도 청구되지 않는지
```

각 스크립트는 실패 시 스크린샷(`*_fail.png`)을 남기고 exit code 1로 끝난다.

## phase2a.mjs 가 확인하는 것

- 주간 루프가 반복된다: 일정 편성 → 성장/작곡 → 공연 → 보상 → 커리어/시설 → 다음 주
- 활동 선택이 실제로 다르게 작용한다 (연습 = 경험치·피로, 휴식 = 회복, 홍보 = 팬)
- 곡이 계속 만들어지고 발매되며, 곡 제목이 중복되지 않는다
- 첫 공연 이후에도 공연 제안이 다시 들어오고, 팬 수에 따라 공연장이 바뀐다
- 주간 결과가 한 번만 확정된다 (화면 재진입·새로고침으로 중복 지급 없음)
- 저장 → 새로고침 → 로드 후 세이브가 완전히 동일하다
- Stage 1 → Stage 2 전환과 월드 오브젝트 조작에 회귀가 없다
